# 通用报告的讲解与交付

读者固定为认真自学的同行。默认提供完整的中文长篇报告；明确请求英文、短评或其他格式时遵循请求。读者应能从报告重建核心方法、复算关键例子，并判断结论由哪些证据支持。

先读取任务相关的原始材料，包括文档、源码、数据、课程或研究文献；论文任务读取全文和相关附录。记录版本、章节、公式编号、图表编号；代码记录提交和文件位置。读取失败时继续使用官方网页、搜索和可用浏览器获取材料。工作记录保存在审计源码或独立验证记录中，正文直接讲知识、机制和证据。

事实、来源作者的解释、报告作者的推导和报告作者的判断分别追溯到来源或写出的推理。给出明确结论，并紧接比较维度、成立条件和依据。证据不足时写清已知结果和缺失证据；语言强度服从证据，不能把消除含糊措辞变成编造确定性。

比较资料时解释它们在问题、假设、机制或证据上的关系。并列性能值使用相同任务、指标、分母和计算预算；条件不同时明确写出各自条件和可比较的范围。

## 讲解深度

关键定义交代对象、符号、维度、取值域和假设。首次出现术语时给出中文名与英文全称或缩写。统一后续符号和称呼。

每个决定结论的推导按以下方式展开：

1. 写出起始定义或已知命题。
2. 在行间公式中逐步变换；每步说明所用恒等式、假设、独立性、近似或不等式。
3. 解释分母、掩码、求和范围、边界条件以及等号成立条件。
4. 给出可复算的小例子或边界反例，解释数学对象如何对应算法行为。
5. 将结论接回所解释的问题、机制与证据。

定理证明覆盖所需引理、每个关键推理和结论成立条件。原文省略的步骤应在可以验证时补齐，并标注为报告中的补充推导。无法证明的命题按原文命题和已知依据呈现，写明证明缺口。保留精确性，不以自然语言略过关键数学步骤。

算法说明输入、输出、状态、初始化、终止条件和复杂度。伪代码与公式、实现的控制流一致。工程技术报告从一次实际输入沿调用链讲到输出，解释状态变化、异常路径、资源成本和接口契约。只有已经执行验证的观察才称为运行结果。

每个关键实验交代问题、设置、对照、指标、结果和由此支持的结论。性能比较区分系统整体效果与组件消融；训练和推理成本分别说明。理论文章使用假设、引理和证明依赖组织证据。

图用于解释结构、因果路径、状态或数量关系。图前说明阅读目的，图注说明具体结论和来源；示意值与实测值分别标注。选择交互前写清读者操作和它揭示的关系。交互可以展示参数变化、注意力权重、状态更新或算法分支；主要结论、完整推导和证据始终在正文可读。

长篇解释使用连续的语义章节、段落与行间公式。并列项使用列表，比较事实使用表格。概览卡片只承载导航或并列事实；详细推导保留在正文。重要证明默认展开，补充内容可以折叠。

## 组织与交付

默认生成项目允许的 outputs/ 中的一份 HTML 和可编辑审计 Markdown；用户指定目录时遵循指定目录。图片、CSS、数学字体和必要脚本内嵌，页面断网可读。长文包含主要章节目录、稳定锚点和来源定位；导航与标签使用实际主题名称及通用报告用语。

默认仅保留少量主要章节，用自然段承接同一论证。小例子、单条公式和推导步骤融入所属章节；主题确实改变时再分节。避免连续短小 subsection、固定五层图谱和机械重复的小标题。Markdown 使用 # 与必要的 ##；HTML 对应 h1 与 h2，复杂章节确需分支时再用 h3。采用适合长文的行宽、明确的段落间距和打印样式。数学使用 KaTeX 或等价渲染，并保留可访问语义。为窄屏公式与表格提供局部横向滚动，整页保持正常宽度。

交付前核对来源覆盖、数学与数据、代码解释、图片、锚点、窄屏和打印布局。实际打开页面检查公式、目录和交互。审查每段是否只讲一件事、每个判断是否有依据，以及全部原文写作规则是否落实。渲染测试只验证工具与格式；科学结论仍须逐项核对来源与推导。
